title: Schedule tasks from a module
description: Define scheduled tasks in the module provider with configureSchedules() and check them with schedule:list.
---

import { Steps } from '@astrojs/starlight/components';

To run a task from the `Blog` module on a schedule, override `configureSchedules()` in the module service provider. You need an enabled `Blog` module and a command to schedule (see [Add Artisan commands to a module](/laravel-modules/guides/console-and-events/commands/)).

<Steps>

1. Uncomment `configureSchedules()` in `Modules/Blog/app/Providers/BlogServiceProvider.php` and register your scheduled command. The generated provider already imports `Illuminate\Console\Scheduling\Schedule`.

   ```php title="Modules/Blog/app/Providers/BlogServiceProvider.php"
   protected function configureSchedules(Schedule $schedule): void
   {
       $schedule->command('blog:prune-old')->daily();
   }
   ```

   Use `protected` or `public` visibility (not `private`) with the `Schedule` parameter.

2. Check the result.

   ```bash
   php artisan schedule:list
   ```

   ```text
   0 0 * * *  php artisan blog:prune-old .......... Next Due: <time>
   ```

</Steps>

## Schedule a command that takes arguments

Pass command arguments as an array:

```php title="Modules/Blog/app/Providers/BlogServiceProvider.php"
$schedule->command('module:prune', ['Blog'])->daily();
```

## When the schedule is built

`configureSchedules()` skips web requests. It runs only when Laravel resolves `Schedule` (such as during `schedule:run` or `schedule:list`), after every service provider has booted. Disabling the module removes its scheduled tasks.

## See the module of a task on the actuator

With [nwidart/laravel-actuator](https://github.com/nWidart/laravel-actuator) version 1.5 or later installed (it adds `Actuator::tagScheduledTasksUsing()`), each task that `configureSchedules()` adds has a `module` tag on the `scheduledtasks` endpoint. The tag holds the module name, as `Module::getName()` gives it. This covers every kind of task: commands, jobs, closures and shell commands.

```json
{
  "runnable": { "target": "php artisan blog:prune-old" },
  "expression": "0 0 * * *",
  "timezone": "UTC",
  "nextExecution": { "time": "2026-01-02T00:00:00+00:00" },
  "tags": { "module": "Blog" }
}
```

A task scheduled outside a module, such as in `routes/console.php`, has no `module` tag, also when it runs a command of a module. Expose the endpoint with `scheduledtasks` in `exposure.include` of `config/actuator.php`. With an actuator before 1.5, the endpoint has no tags.
