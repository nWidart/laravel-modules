description: Implement ActivatorInterface, register it under activators.<key>.class, and select it with activator.

To store the enabled or disabled status of modules somewhere other than `modules_statuses.json`, write a class that implements `ActivatorInterface` and select it in `config/modules.php`. This guide builds an activator that keeps one status file for each environment, such as `modules_statuses.local.json` and `modules_statuses.production.json`.

The package creates the activator with `new $class($app)` while it registers, before the application has booted. The constructor and the methods may use the container and the file system, but not a service that needs a booted application, such as the database.

<Steps>

1. Create the class.

   ```php title="app/Support/EnvironmentActivator.php"
   <?php

   namespace App\Support;

   use Illuminate\Contracts\Foundation\Application;
   use Nwidart\Modules\Contracts\ActivatorInterface;
   use Nwidart\Modules\Module;

   class EnvironmentActivator implements ActivatorInterface
   {
       private string $file;

       /** @var array<string, bool> */
       private array $statuses = [];

       public function __construct(Application $app)
       {
           $this->file = $app->basePath('modules_statuses.'.$app->environment().'.json');

           if (is_file($this->file)) {
               $this->statuses = json_decode(file_get_contents($this->file), true) ?: [];
           }
       }

       public function enable(Module $module): void
       {
           $this->setActiveByName($module->getName(), true);
       }

       public function disable(Module $module): void
       {
           $this->setActiveByName($module->getName(), false);
       }

       public function hasStatus(Module|string $module, bool $status): bool
       {
           $name = $module instanceof Module ? $module->getName() : $module;

           // A module without an entry counts as disabled.
           return ($this->statuses[$name] ?? false) === $status;
       }

       public function setActive(Module $module, bool $active): void
       {
           $this->setActiveByName($module->getName(), $active);
       }

       public function setActiveByName(string $name, bool $active): void
       {
           $this->statuses[$name] = $active;
           $this->save();
       }

       public function delete(Module $module): void
       {
           unset($this->statuses[$module->getName()]);
           $this->save();
       }

       public function reset(): void
       {
           $this->statuses = [];

           if (is_file($this->file)) {
               unlink($this->file);
           }
       }

       private function save(): void
       {
           file_put_contents($this->file, json_encode($this->statuses, JSON_PRETTY_PRINT));
       }
   }
   ```

2. Register the class under a key of your choice, and select that key. Publish the config file first if you have not:

   ```bash
   php artisan vendor:publish --provider="Nwidart\Modules\LaravelModulesServiceProvider" --tag=config
   ```

   ```php title="config/modules.php"
   'activators' => [
       'file' => [
           'class' => FileActivator::class,
           'statuses-file' => base_path('modules_statuses.json'),
       ],
       'environment' => [
           'class' => \App\Support\EnvironmentActivator::class,
       ],
   ],

   'activator' => 'environment',
   ```

3. Carry over the current statuses. The new activator starts with no entries, so every module counts as disabled. Copy the old file to the file of your environment. The file name uses the value of `APP_ENV`, here `local`:

   ```bash
   cp modules_statuses.json modules_statuses.local.json
   ```

   Or enable the modules again with `php artisan module:enable --all`.

4. Check the result.

   ```bash
   php artisan module:disable Blog
   php artisan module:list
   cat modules_statuses.local.json
   ```

   `module:list` shows `Blog` as `[Disabled]`, and the JSON file has `"Blog": false`. The old `modules_statuses.json` did not change.

</Steps>

The class name must exist when the package registers: an unknown `activator` key, a missing `class` entry or a class that does not exist throws `InvalidActivatorClass`.
