## Install from Composer

Composer puts the module in `vendor/`, so the package must scan `vendor/`.

<Steps>

1. Enable the scan in `config/modules.php`.

   ```php title="config/modules.php"
   'scan' => [
       'enabled' => true,
       'paths' => [
           base_path('vendor/*/*'),
       ],
   ],
   ```

2. Install the module. The second argument is a Composer version constraint. Without it, the command installs `dev-master`, which fails when the package has no `master` branch: pass a version.

   ```bash
   php artisan module:install acme/blog 1.2.0
   ```

   The command runs `composer require acme/blog:1.2.0`, then `module:update Blog`. The last part of the package name, in studly case, must be the module name: `acme/blog` for `Blog`. Otherwise the command prints that it cannot find the module and exits with `1`.

3. Enable the module. A module without an entry in `modules_statuses.json` is disabled.

   ```bash
   php artisan module:enable Blog
   ```

</Steps>

## Install from Git

To clone the module into the modules folder (`Modules/Blog`), pass `--type`.

<Steps>

1. Install the module.

   ```bash
   php artisan module:install acme/blog 1.2.0 --type=github-https
   ```

   The command runs `git clone https://github.com/acme/blog.git Modules/Blog`, checks out `1.2.0` (a branch, tag or commit, `master` by default), then runs `module:update`. The module name is the `name` in the `module.json` of the clone.

   `--type` takes `github` (SSH), `github-https`, `gitlab`, `bitbucket`, or a repository URL. To install to another folder, add `--path=Modules/Blog`.

2. Regenerate the autoloader, so that the merge plugin reads the `composer.json` of the new module.

   ```bash
   composer dump-autoload
   ```

3. Enable the module.

   ```bash
   php artisan module:enable Blog
   ```

</Steps>

To keep the module code in the history of your application instead of a nested clone, add `--tree`. The command adds a Git remote named `Blog` and runs `git subtree add --squash`. The destination must be inside the project.

```bash
php artisan module:install acme/blog 1.2.0 --type=github-https --tree
```

## Install a set of modules

To install several modules with one command, list them in `modules.json` in the application root.

<Steps>

1. Create the file.

   ```json title="modules.json"
   {
       "require": [
           {
               "name": "acme/blog",
               "version": "1.2.0",
               "type": "github-https"
           },
           {
               "name": "acme/shop",
               "version": "^2.0"
           }
       ]
   }
   ```

   An entry without `type` installs from Composer.

2. Run the command without a name.

   ```bash
   php artisan module:install
   ```

   The command installs each entry in order. If one fails, it installs the others and exits with `1`.

</Steps>

## Update a module

To install the Composer packages that a module requires, run `module:update`.

```bash
php artisan module:update Blog
```

The command runs `composer require` for the `require` and `require-dev` entries of the module `composer.json`, and merges its `scripts` into the `composer.json` of the application. Use `--all` for every module. It does not fetch a newer version of the module itself. For a Composer module, run `composer update acme/blog`. For a Git module, pull in its folder.

To skip `module:update` during an install, add `--no-update`.

### Check the result

```bash
php artisan module:list
```

The list shows `Blog` as enabled.
