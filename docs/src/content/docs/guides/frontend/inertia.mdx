At the end, the `Blog` module renders Inertia pages from `Modules/Blog/resources/js/Pages`, and the application resolves them by name.

Prerequisites:

- Inertia v3 is installed in your application as the [Inertia documentation](https://inertiajs.com) describes. The package does not install Inertia, and the stubs target Inertia v3 only.
- Server: `inertiajs/inertia-laravel` `^3`.
- Client: `@inertiajs/vue3` (Vue 3), `@inertiajs/react` (React 19), or `@inertiajs/svelte` (Svelte 5), all `^3`.
- Your root Blade view loads `resources/js/app.js` with `@vite` and renders `@inertia`. With React, place `@viteReactRefresh` before `@vite` for `npm run dev`.

## Generate an Inertia module

<Steps>

1. Choose the frontend framework for generated pages. The default is `vue`.

   To use React or Svelte, publish the configuration and set `inertia.frontend`. If `config/modules.php` already exists, edit the existing file.

   ```bash
   php artisan vendor:publish --provider="Nwidart\Modules\LaravelModulesServiceProvider" --tag=config
   ```

   ```php title="config/modules.php"
   'inertia' => [
       'frontend' => 'react', // vue, react or svelte
   ],
   ```

   `module:make` reads this key and accepts no framework flag of its own.

2. Create the module.

   ```bash
   php artisan module:make Blog --inertia
   ```

   The command generates `BlogController` and four pages (`Index`, `Create`, `Show`, and `Edit`) in `Modules/Blog/resources/js/Pages`. It skips Blade views. Combining `--inertia` with `--plain` writes no Inertia files.

3. Publish the Inertia entry file so Vite resolves pages from every module.

   <Tabs syncKey="inertia-frontend">
     <TabItem label="Vue">
       ```bash
       php artisan module:publish-inertia --vue
       ```
     </TabItem>
     <TabItem label="React">
       ```bash
       php artisan module:publish-inertia --react
       ```
     </TabItem>
     <TabItem label="Svelte">
       ```bash
       php artisan module:publish-inertia --svelte
       ```
     </TabItem>
   </Tabs>

   Pass at most one framework flag, or omit it to use `inertia.frontend`. The command writes `resources/js/app.js` and asks before overwriting an existing file. Move any custom code out of `resources/js/app.js` first, then pass `--force` to overwrite without a prompt.

   See [`module:publish-inertia`](/laravel-modules/reference/commands/publish/#modulepublish-inertia) for flag validation, exit codes, and how the published entry mounts the app.

   <Aside type="note" title="Upgrading from an earlier version">
   A React `app.js` published by an earlier version contains JSX and fails to build on Vite. Republish React and Svelte entry files with `--force`: `php artisan module:publish-inertia --react --force` or `--svelte --force`.
   </Aside>

4. Register your framework plugin in the root `vite.config.js`. Keep your existing plugins and options, and make sure `resources/js/app.js` is in `laravel({ input: [...] })`. Install the plugin package with npm if needed.

   <Tabs syncKey="inertia-frontend">
     <TabItem label="Vue">
       ```js title="vite.config.js"
       import vue from '@vitejs/plugin-vue'

       // in defineConfig({ plugins: [...] }): add the plugin call, keep the rest
       vue(),

       // in your existing laravel({...}) call: input must include the entry file
       // input: ['resources/css/app.css', 'resources/js/app.js'],
       ```
     </TabItem>
     <TabItem label="React">
       ```js title="vite.config.js"
       import react from '@vitejs/plugin-react'

       // in defineConfig({ plugins: [...] }): add the plugin call, keep the rest
       react(),

       // in your existing laravel({...}) call: input must include the entry file
       // input: ['resources/css/app.css', 'resources/js/app.js'],
       ```
     </TabItem>
     <TabItem label="Svelte">
       ```js title="vite.config.js"
       import { svelte } from '@sveltejs/vite-plugin-svelte'

       // in defineConfig({ plugins: [...] }): add the plugin call, keep the rest
       svelte(),

       // in your existing laravel({...}) call: input must include the entry file
       // input: ['resources/css/app.css', 'resources/js/app.js'],
       ```

       You can ignore the `[vite-plugin-svelte] no Svelte config found` build message.
     </TabItem>
   </Tabs>

5. Build the assets.

   ```bash
   npm run build
   ```

</Steps>

### How a page name resolves

The generated controller returns `Inertia::render('Blog/Index')`. The first segment is the module folder name (case-sensitive), and the rest is the path under `resources/js/Pages`:

| Page name | File |
| --- | --- |
| `Blog/Index` | `Modules/Blog/resources/js/Pages/Index.vue` |
| `Blog/Posts/Show` | `Modules/Blog/resources/js/Pages/Posts/Show.vue` |

The file extension matches your framework (`.vue`, `.jsx`, or `.svelte`). If no module page matches, the entry file falls back to `resources/js/Pages/<name>`.

### Check the result

Keep `npm run dev` running or run `npm run build`, then serve the application (for example with `php artisan serve`). Open `/blogs` to verify the `Index` page renders. Run `php artisan route:list --name=blog` to inspect the generated routes.

## Render Inertia pages on the server

Server-side rendering (SSR) sends rendered HTML with the first response. The browser then hydrates it. This section uses Inertia v3 SSR and the `@inertiajs/vite` plugin.

<Steps>

1. Publish the SSR files. Add `--force` when `resources/js/app.js` exists, which a new Laravel 13 application includes.

   <Tabs syncKey="inertia-frontend">
     <TabItem label="Vue">
       ```bash
       php artisan module:publish-inertia --vue --ssr --force
       ```
     </TabItem>
     <TabItem label="React">
       ```bash
       php artisan module:publish-inertia --react --ssr --force
       ```
     </TabItem>
     <TabItem label="Svelte">
       ```bash
       php artisan module:publish-inertia --svelte --ssr --force
       ```
     </TabItem>
   </Tabs>

   The command writes three files to `resources/js/` and writes nothing if it cannot write all of them:

   - `app.js`: the client entry. It hydrates server-rendered pages and mounts the others, so it also works while the SSR server is stopped.
   - `ssr.js`: the server entry. `@inertiajs/vite` finds it by name and wraps it in the SSR server. Keep its `createInertiaApp` call at the top level, not inside an `if`.
   - `inertia-pages.js`: the page resolver both entries share.

2. Install the Inertia Vite plugin.

   ```bash
   npm install -D @inertiajs/vite
   ```

3. Add `inertia()` to the plugins in `vite.config.js`, after `laravel(...)`. Make sure `resources/js/app.js` is in `laravel({ input: [...] })`.

   <Tabs syncKey="inertia-frontend">
     <TabItem label="Vue">
       ```js title="vite.config.js"
       import vue from '@vitejs/plugin-vue'
       import inertia from '@inertiajs/vite'

       // in defineConfig({ plugins: [...] }): keep laravel(...) and add the others after it
       vue(),
       inertia(),
       ```
     </TabItem>
     <TabItem label="React">
       ```js title="vite.config.js"
       import react from '@vitejs/plugin-react'
       import inertia from '@inertiajs/vite'

       // in defineConfig({ plugins: [...] }): keep laravel(...) and add the others after it
       react(),
       inertia(),
       ```
     </TabItem>
     <TabItem label="Svelte">
       ```js title="vite.config.js"
       import { svelte } from '@sveltejs/vite-plugin-svelte'
       import inertia from '@inertiajs/vite'

       // in defineConfig({ plugins: [...] }): keep laravel(...) and add the others after it
       svelte(),
       inertia(),
       ```
     </TabItem>
   </Tabs>

4. Build the client and the server bundle. Set the `build` script in `package.json`, then run it.

   ```json title="package.json"
   "scripts": {
       "build": "vite build && vite build --ssr"
   }
   ```

   ```bash
   npm run build
   ```

   The build prints `Inertia SSR entry: resources/js/ssr.js` and writes `bootstrap/ssr/ssr.js`. `inertia-laravel` finds that file without extra configuration. `config/inertia.php` enables SSR by default (`ssr.enabled`).

5. In production, start the SSR server and keep it running.

   ```bash
   php artisan inertia:start-ssr
   ```

</Steps>

### SSR in development

`npm run dev` renders SSR through Vite, so you do not run `inertia:start-ssr` locally. The first request right after Vite starts can come back client-rendered while Vite warms up.

### Module pages with SSR

`inertia-pages.js` resolves a name like `Blog/Posts/Index` to `Modules/Blog/resources/js/Pages/Posts/Index.<ext>` first, then to `resources/js/Pages/Blog/Posts/Index.<ext>`. An unknown name throws `Inertia page not found: <name>`.

The package uses this resolver because the `pages` option of `@inertiajs/vite` takes one directory, so it cannot also search `Modules/*/resources/js/Pages`.

<Aside type="caution" title="Browser APIs">
The server renders pages without `document` or `window`. Use them only in mount hooks such as `onMounted` (Vue), `useEffect` (React), or `onMount` (Svelte).
</Aside>

### Stop using SSR

Running `module:publish-inertia --force` without `--ssr` rewrites only `app.js`. It leaves `ssr.js` and `inertia-pages.js` in place. Delete both files, restore the `build` script to `vite build`, and remove `inertia()` from `vite.config.js` if you no longer want SSR.

## Add a page

Run `module:make-inertia-page` to add a page to an existing module.

```bash
php artisan module:make-inertia-page Posts/Index Blog
```

This writes `Modules/Blog/resources/js/Pages/Posts/Index.vue` (using `inertia.frontend` by default). Add `--vue`, `--react`, or `--svelte` to override the framework for that page, passing at most one flag.

Render the page from a controller with `Inertia::render('Blog/Posts/Index')`. Run `npm run build` or keep `npm run dev` running so Vite picks up the new file.

## Add a component

```bash
php artisan module:make-inertia-component PostCard Blog
```

This writes `Modules/Blog/resources/js/Components/PostCard.vue`. The extension follows `inertia.frontend` or a single `--vue`, `--react`, or `--svelte` flag.

## Add an Inertia controller

```bash
php artisan module:make-controller PostController Blog --inertia
```

The generated resource methods render `Blog/Index`, `Blog/Create`, `Blog/Show`, and `Blog/Edit`. Update the page names in the controller if you want paths like `Blog/Posts/Index`, and generate those pages with `module:make-inertia-page`.

## Add the Inertia middleware

```bash
php artisan module:make-middleware HandleInertiaRequests Blog --inertia
```

This writes `Modules/Blog/app/Http/Middleware/HandleInertiaRequests.php`, extending `Inertia\Middleware` with `$rootView = 'app'`. Register it in `bootstrap/app.php` in place of `App\Http\Middleware\HandleInertiaRequests` so only one Inertia middleware runs in the `web` group.

```php title="bootstrap/app.php"
->withMiddleware(function (Middleware $middleware): void {
    $middleware->web(append: [
        \Modules\Blog\Http\Middleware\HandleInertiaRequests::class,
    ]);
})
```
