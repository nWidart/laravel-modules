At the end, the `Blog` module serves compiled CSS and JavaScript. Pick one of two ways: a build for each module, or one build for the whole application. Both need a `Blog` module and Node.js. See [Create a module](/laravel-modules/guides/modules/create-a-module/).

## Build a module on its own

Use this way when a module has its own assets and its own build. The build writes to `public/build-blog`.

`module:make Blog` generates `Modules/Blog/vite.config.js` and `Modules/Blog/package.json`. The generated `package.json` pins `vite` `^8.0.0`, `laravel-vite-plugin` `^3.1` and `sass` `^1.70.0`, the same constraints as a new Laravel 13 application. Vite 8 and `laravel-vite-plugin` 3 need Node.js `^20.19.0 || >=22.12.0`. npm 11 can print an `install-scripts` warning for `@parcel/watcher`, a dependency of `sass`. The warning does not stop the build.

:::note
A module generated by an earlier version keeps its `package.json` and `vite.config.js`. Vite 5 and later write `manifest: true` to `.vite/manifest.json`, but `module_vite()` reads `manifest.json` in the build directory. When you move such a module to Vite 5 or later, change the `build` option in its `vite.config.js` to `manifest: 'manifest.json'`. Without it, `module_vite()` fails with `Vite manifest not found at: .../public/build-blog/manifest.json`.
:::

<Steps>

1. Install the dependencies in the module folder.

   ```bash
   cd Modules/Blog
   npm install
   ```

2. Add a rule to `resources/assets/sass/app.scss`. The generated file is empty, and an empty file builds to a JavaScript chunk, not a stylesheet: the layout then gets two `<script type="module">` tags and no stylesheet link.

   ```scss title="Modules/Blog/resources/assets/sass/app.scss"
   body {
       color: #222;
   }
   ```

3. Build the assets.

   ```bash
   npm run build
   ```

   The generated `vite.config.js` reads `resources/assets/sass/app.scss` and `resources/assets/js/app.js`. It writes the build and its manifest to `public/build-blog` (`../../public/build-blog` from the module folder).

4. Load the build in the layout. The generated layout has the two `module_vite()` calls commented out. Remove the Blade comment markers.

   ```blade title="Modules/Blog/resources/views/components/layouts/master.blade.php"
   {{-- in <head> --}}
   {{ module_vite('build-blog', 'resources/assets/sass/app.scss') }}

   {{-- before </body> --}}
   {{ module_vite('build-blog', 'resources/assets/js/app.js') }}
   ```

   The first argument is the build directory, `build-<lower case module name>`. The second is the entry point, as written in `input` of the module `vite.config.js`, relative to the module folder.

</Steps>

To use a Vue, React or Svelte plugin, uncomment its import and its entry in `plugins` in `Modules/Blog/vite.config.js`, then install the plugin package in `Modules/Blog`.

### Check the result

After the build, `public/build-blog/manifest.json` exists. Open a page that uses the layout and look for a `<link rel="stylesheet">` and a `<script type="module">` that point to `/build-blog/assets/`.

## Build module assets from the application

Use this way to run one Vite build, from the application root, for the application and every enabled module.

<Steps>

1. Publish the module loader to the application root.

   ```bash
   php artisan vendor:publish --tag=vite
   ```

   This copies `vite-module-loader.js` to the application root.

   The command does not overwrite an existing file. If an older loader is there, it prints `File [vite-module-loader.js] already exists .. SKIPPED`, and the build in step 2 then fails with `"moduleRefreshPaths" is not exported by "vite-module-loader.js"`. Add `--force` to replace the file.

   ```bash
   php artisan vendor:publish --tag=vite --force
   ```

2. Change your root `vite.config.js`. Keep its plugins and options, and wrap the config in the async `getConfig()`. `collectModuleAssetsPaths(paths, 'Modules')` appends the `paths` of every enabled module to the list you give it. The file below is the default of a new Laravel 13 app with the added lines marked. The `input` and `refresh` lines of the default file are replaced (lines 17 and 18), and `refreshPaths` is added to the import on line 2. Everything else is the default file. If your file differs, keep your own plugins and options.

   ```js title="vite.config.js" ins={2,4,7-12,14,17-18,32,34}
   import { defineConfig } from 'vite';
   import laravel, { refreshPaths } from 'laravel-vite-plugin';
   import { bunny } from 'laravel-vite-plugin/fonts';
   import collectModuleAssetsPaths, { moduleRefreshPaths } from './vite-module-loader.js';
   import tailwindcss from '@tailwindcss/vite';

   async function getConfig() {
       const paths = [
           'resources/css/app.css',
           'resources/js/app.js',
       ];
       const allPaths = await collectModuleAssetsPaths(paths, 'Modules');

       return defineConfig({
           plugins: [
               laravel({
                   input: allPaths,
                   refresh: [...refreshPaths, ...moduleRefreshPaths('Modules')],
                   fonts: [
                       bunny('Instrument Sans', {
                           weights: [400, 500, 600],
                       }),
                   ],
               }),
               tailwindcss(),
           ],
           server: {
               watch: {
                   ignored: ['**/storage/framework/views/**'],
               },
           },
       });
   }

   export default getConfig();
   ```

   The loader imports the `vite.config.js` of each enabled module and reads its `paths` export. The `vite.config.js` generated by `module:make` already exports `paths`, so you do not change it. If a module's file fails to load, the loader prints `Skipping the assets of module <Name>: could not load ...` and continues with the other modules.

   The loader reads `modules_statuses.json` in the application root. It adds only the modules whose status is `true`. `moduleRefreshPaths('Modules')` returns the Blade, `lang` and `routes` globs of every module, so a change in a module reloads the page.

3. Build the assets.

   ```bash
   npm install sass
   npm run build
   ```

   Install `sass` because the entry points include an SCSS file.

4. Load the entry points with `@vite` in the layout.

   ```blade title="Modules/Blog/resources/views/components/layouts/master.blade.php"
   @vite([
       'Modules/Blog/resources/assets/sass/app.scss',
       'Modules/Blog/resources/assets/js/app.js',
   ])
   ```

</Steps>

### Check the result

Open `public/build/manifest.json`. It has an entry named `Modules/Blog/resources/assets/js/app.js`. To find out whether a module is picked up, enable and disable it in `modules_statuses.json` and build again: the entry follows the status.

## Publish static assets

To serve files that Vite does not process, put them in `Modules/Blog/resources/assets` and publish them.

<Steps>

1. Publish the assets of the module.

   ```bash
   php artisan module:publish Blog
   ```

   The command copies `Modules/Blog/resources/assets` to `public/modules/blog` and overwrites existing files.

2. Link to a published file.

   ```blade title="Modules/Blog/resources/views/index.blade.php"
   <img src="{{ Module::asset('blog:images/logo.png') }}" alt="Blog">
   ```

   The format is `<lower case module name>:<path in the assets folder>`. The URL starts with `//`, without `http:` or `https:`.

</Steps>

### Check the result

Open `/modules/blog/images/logo.png` in the browser.
