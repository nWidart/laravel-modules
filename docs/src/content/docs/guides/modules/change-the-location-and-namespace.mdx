---

import { Steps } from '@astrojs/starlight/components';

To store modules in `app-modules/` under the `AppModules` root namespace, update `paths.modules` and `namespace` in `config/modules.php`, plus the `merge-plugin` glob in `composer.json`. Publish `config/modules.php` first if you have not already:

```bash
php artisan vendor:publish --provider="Nwidart\Modules\LaravelModulesServiceProvider" --tag=config
```

<Steps>

1. Update the namespace and modules path in `config/modules.php`.

   ```php title="config/modules.php"
   'namespace' => 'AppModules',

   'paths' => [
       'modules' => base_path('app-modules'),
       // ...
   ],
   ```

2. Update the `merge-plugin` glob in `composer.json` so Composer autoloads classes from the new folder.

   ```json title="composer.json"
   "extra": {
       "merge-plugin": {
           "include": [
               "app-modules/*/composer.json"
           ]
       }
   }
   ```

3. Rebuild the autoloader.

   ```bash
   composer dump-autoload
   ```

4. Create a module and verify its location and namespace.

   ```bash
   php artisan module:make Blog
   ```

   This creates `app-modules/Blog`. Its `composer.json` maps `AppModules\Blog\` to `app/`, and `module.json` registers `AppModules\Blog\Providers\BlogServiceProvider`.

</Steps>

## Move modules that already exist

Config changes do not move or rewrite existing modules. Migrate each existing module manually:

<Steps>

1. Move the module folder.

   ```bash
   mkdir -p app-modules
   mv Modules/Blog app-modules/Blog
   ```

2. If you changed `namespace`, replace `Modules\Blog` (and escaped `Modules\\Blog` in `module.json` and `composer.json`) with `AppModules\Blog`. This command leaves `Nwidart\Modules\...` untouched:

   ```bash
   grep -rl 'Modules' app-modules/Blog | xargs perl -pi -e 's/(?<!\w)(?<!\w\\)Modules(\\{1,2})Blog\b/AppModules$1Blog/g'
   ```

3. Update the `merge-plugin` glob in `composer.json` as above and run `composer dump-autoload`.

4. Check the result.

   ```bash
   php artisan module:list
   ```

   `Blog` shows `app-modules/Blog` as its path. Its enabled status stays unchanged because `modules_statuses.json` is keyed by module name.

</Steps>

Update imports of the old namespace in your application code manually. `module:composer-update` does not rename namespaces; it only updates legacy `Modules\<Name>\App\` PSR-4 entries.
