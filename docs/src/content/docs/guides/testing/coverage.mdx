---
title: Include modules in code coverage
description: Add the code of the enabled modules to the source list of phpunit.xml so that the coverage report includes it.
---

import { Steps } from '@astrojs/starlight/components';

At the end, your application's coverage report includes `Modules/Blog/app`. Prerequisites: `phpunit.xml` in the application root, `modules_statuses.json`, and a coverage driver (Xdebug or PCOV).

<Steps>

1. Update `phpunit.xml`.

   ```bash
   php artisan module:update-phpunit-coverage
   ```

   The command reads the statuses file configured in `modules.activators.file.statuses-file` (default `modules_statuses.json`). It adds each enabled module's `app` folder to `<source><include>` and removes disabled or deleted modules.

   ```xml title="phpunit.xml"
   <source>
       <include>
           <directory>app</directory>
           <directory suffix=".php">./Modules/Blog/app/</directory>
       </include>
   </source>
   ```

   See [`module:update-phpunit-coverage`](/laravel-modules/reference/commands/utility/#moduleupdate-phpunit-coverage) for supported `<source>` XML layouts and exit codes.

2. Run the tests with coverage.

   ```bash
   php artisan test --coverage
   ```

   With Xdebug, enable coverage mode for the run:

   ```bash
   XDEBUG_MODE=coverage php artisan test --coverage
   ```

</Steps>

Re-run `php artisan module:update-phpunit-coverage` whenever you add, remove, enable, or disable a module. Make sure your module tests are part of a PHPUnit test suite; see [Run the tests of a module](/laravel-modules/guides/testing/run-module-tests/).

## Check the result

Open `phpunit.xml` and confirm `./Modules/Blog/app/` appears under `<source><include>`. The coverage output lists files under `Modules/Blog/app`.

If the command exits with a non-zero status, check the exit code reference in [`module:update-phpunit-coverage`](/laravel-modules/reference/commands/utility/#moduleupdate-phpunit-coverage).
